# 萌战系统

站内每年一届的萌王大赛：提名 → 审核 → 海选 → 小组赛 → 淘汰赛 → 决赛，全程线上投票。

![赛事中心](../screenshots/contest-center.webp)

## 1. 赛制总览

```text
提名期（5 天） → 审核期（3 天） → 海选（5 天：4 票 + 1 公示）
  → 小组赛（15 天：3 轮，每轮 4 票 + 1 公示）
  → 淘汰赛（15 天：16 强→8 强→4 强，每轮 4 票 + 1 公示）
  → 决赛（7 天：4 票 + 3 公示）
总时长约 50 天，各阶段按预设时间自动切换
```

投票规则：

| 阶段 | 每人票数 | 限制 |
|---|---|---|
| 提名期 | 最多提名 5 个角色 / 人 | 角色名唯一，先到先得；必填角色名、作品名、性别、角色图 |
| 海选 | 每组 15 票 | 最多投给 5 个角色，单个角色最多 3 票 |
| 小组赛 | 每轮 1 票 | 组内单循环 3 轮，积分制：胜 +3 / 平 +1 / 负 +0 |
| 淘汰赛 | 每轮 1 票 | 1v1 单败：16 强 → 8 强 → 4 强 → 决赛 |
| 决赛 | 1 票 | 平票时比较海选总票数，仍相同按对阵顺位 |

> 匿名投票、只设支持票、禁止拉票刷票、过期自动关闭。

## 2. 状态机（代码视角）

`app/contest_engine.py` 是唯一"权威裁判"，页面只读它的结果：

```text
status: open → (提名) → review? → 海选 → 小组赛 → 淘汰赛 → 决赛 → finished
          │
          └─ 阶段切换依据 contests.open_at / close_at + config 里的天数配置
```

- 页面展示的"当前阶段、剩余时间、对阵"都从引擎算出来，**不信任前端**。
- 每一轮结束由引擎写回晋级结果；重复调用是幂等的（不会重复加分/重复晋级）。
- 所有失败路径（人数不足、缺员、双方禁赛）都有明确规则，见下节。

## 3. 特殊状态处理（易错规则）

| 情况 | 处理 |
|---|---|
| **禁赛** | 禁赛角色不能被投票、不能晋级；已排定对阵自动判负，对手不战而胜；全程显示禁赛标识 |
| **双禁赛** | 同一场双方均禁赛 → 本场无人晋级，由该轮票数最高的合法落败者替补（复活赛制），保证后续轮次人数完整 |
| **轮空** | 对阵缺员或人数为奇数 → 自动产生轮空场，无对手方直接晋级 |
| **人数不足** | 海选出线不足 32 人 → 自动缩编小组数量（至少保留一组），缺额以轮空槽占位 |
| **平票** | 淘汰赛：比较海选总票数 → 仍相同按对阵顺位；小组赛：积分 → 总票数 |
| **冠军空缺** | 决赛双方均无法完赛 → 该届冠军空缺，只公布其后排名 |

!!! danger "改规则前先看测试"
    `tests/test_contest_engine.py` 有 40+ 条用例专门锁这些边界（双禁赛替补、轮空、缩编、平票、冠军空缺）。
    改引擎之前先跑它；如果规则确实要变，**先改测试再改实现**。

## 4. 赛事详情与投票

![赛事详情](../screenshots/contest-detail.webp)

- 详情页展示当前阶段、倒计时、对阵表、票数（公示期才展示详细票数）。
- 投票接口会校验：登录、赛事状态、阶段是否开放、角色是否禁赛、是否超过个人票数上限。
- 投票记录写 `contest_votes`（含 `user_id`），但**页面不展示投票人**（匿名）。

## 5. 实时票数与对抗进度条

投票页每 10 秒自动拉一次最新票数（`GET /api/contest/<id>/vote-stats`，需登录），不依赖 Supabase 配置：

- **小组赛 / 淘汰赛**：每场对决一条左右对拉进度条，宽度 = 本场两人得票占比；两侧显示百分比、中间显示「共 N 票」
- **海选**：单角色得票占比条（多选制没有两两对决）
- 服务端先渲染初始数据（无 JS 也有条），前端轮询只做增量更新；页面切回前台立即刷新
- 接口失败时角标变「更新暂停」，不会弹错误打断浏览；`prefers-reduced-motion` 下关闭位移动画
- 轮次结束（公示期）自动回退到最近一轮有票的数据

## 6. 分享海报

赛事详情页「📸 生成分享海报」：前端 canvas 画 1200×630 战报图（标题、阶段、累计票数前 6 名条形图、站点地址、日期），
下载为 PNG，可直接发群/空间。画在浏览器端，**不依赖服务器字体**（Vercel 上没有中文字体也能出图）。

## 7. 页面截图与视觉

- 赛事封面存 Storage 的 `contest_images` 桶。
- 卡片进入时用 `card-rise` 统一下沉/淡入动效（尊重设置里的"减少动效"）。
- 票数/对阵等数字每轮由引擎落库，页面不做本地累加，避免多端数据不一致。

## 8. 管理后台相关

管理入口：`/admin/contests/*`，详见 [管理后台](admin.md)。

- 创建赛事时设置男女分组方式（`gender_mode`）、各阶段天数。
- 提名审核：通过 / 驳回，通过后进海选。
- 角色禁赛 / 解禁、删除候选角色。
- 强制结算某轮、修复对阵（谨慎使用，操作不可逆）。
